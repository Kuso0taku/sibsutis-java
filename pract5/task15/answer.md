# Задание 15. Планировщик prerequisites

## Модель

```java
PrerequisiteGraph<V> {
  Map<V, Set<V>> prereqOf;    // курс -> его prerequisites
  Map<V, Set<V>> dependents;  // prereq -> курсы, которым нужен он
  List<V> insertionOrder;     // фиксированный порядок вершин
}
```

Две индексированные карты дают O(1) доступ в обе стороны: «чей это
prerequisite» и «кому этот prereq нужен».

## Выбор коллекций

| Коллекция        | Зачем                                                  |
|------------------|--------------------------------------------------------|
| `HashMap<V, Set>`| доступ к соседям O(1)                                  |
| `LinkedHashSet`  | соседи перебираются в порядке вставки — детерминизм      |
| `List<V>`        | фиксированный порядок вершин для старта/итераций         |

## Порядок и циклы

- **Допустимый порядок** — топологическая сортировка (алгоритм Кана):
  O(V + E). Стартовые вершины и перебор соседей идут по `insertionOrder`,
  поэтому одинаковый ввод дает одинаковый результат.
- **Цикл** — если выпущено меньше вершин, чем зарегистрировано, граф
  зациклен. Для диагностики three-color DFS возвращает замкнутый путь
  `[v1, ..., v1]`, который попадает и в сообщение исключения.

## Поведение при отсутствующей вершине

- `addPrerequisite(course, prereq)` сам регистрирует еще не существующие
  вершины — висячих ссылок не появляется;
- `contains(v)` отвечает честно: независимые вершины, добавленные через
  `register`, тоже попадают в итоговый порядок и не теряются.

## Сложности

| Операция   | Сложность      |
|------------|----------------|
| `register` | O(1) `computeIfAbsent` |
| `addPrerequisite` | O(1) к edge      |
| `order`    | O(V + E)       |
| `findCycle`| O(V + E)       |
