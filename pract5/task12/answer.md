# Задание 12. Generic repository

## Контракт

```java
interface Repository<ID, T> {
  void save(T entity);
  Optional<T> findById(ID id);
  List<T> findAll();
  boolean deleteById(ID id);
}
```

`ID` и `T` — параметры типа; хранилище не знает, чем является сущность.
Реализация получает функцию «взять id из сущности» — это оставляет выбор id
за вызывающим, без смешивания ответственности.

## Решения in-memory реализации

- **Не отдает внутреннюю коллекцию.** `findAll()` возвращает `List.copyOf(...)`
  — неизменяемую копию на момент вызова. Изменение снаружи не портит хранилище,
  а поздние `save` не «просвечивают» в старый снимок (см. тест).
- **Не принимает `null`.** Ни сущность, ни id. `null` — ошибка вызывающего,
  а не состояние репозитория.
- **Семантика повторного `save`.** Тот же id — замена значения (upsert):
  размер не растет, `findById` возвращает новую сущность. Это единственное
  предсказуемое поведение для `put`; молчаливая потеря или дубликат были бы
  хуже, о чем свидетельствует контракт task3.
- **Хранение** — `LinkedHashMap`: O(1) доступ и стабильный порядок вставки
  для `findAll`.
