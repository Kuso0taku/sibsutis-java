# Задание 3. Map и индекс

## Повторный ID без молчаливой перезаписи

`put` затрет старое значение и вернет его — ошибка останется незамеченной.
Поэтому в `CourseIndex.add` используется `putIfAbsent`:

1. `putIfAbsent` вставляет только если ключа нет;
2. `null` в ответе = вставили;
3. не `null` = id уже был → бросаем `IllegalStateException`.

Явная замена вынесена в отдельный метод `replace` (`put`), чтобы намерение
«заменить» было видно в коде.

## Сравнение методов

| Метод              | Что делает                                  | Нюанс                                            |
|--------------------|---------------------------------------------|--------------------------------------------------|
| `get(k)`           | вернуть значение или `null`                 | `null` нельзя отличить «нет ключа» от «значение null» |
| `containsKey(k)`   | есть ли ключ                                | отдельный проход, затем обычно второй `get`      |
| `putIfAbsent(k,v)` | вставить, если ключа нет                    | атомарно для `ConcurrentHashMap`; риск перезаписи отсутствует |
| `computeIfAbsent(k,f)` | вычислить и вставить, если ключа нет    | фабрика вызывается только при промахе            |

`get` + `containsKey` дают два поиска на одну операцию. `computeIfAbsent`
делает «найти или создать» одним вызовом и не выполняет дорогое создание
зря — это видно в тесте по счетчику вызовов фабрики.
