# Задание 13. Обратный индекс

## Структура

```java
Map<Tag, Set<CourseId>>
```

По тегу — множество курсов. Поиск «все курсы по тегу» — O(1), а не полный
перебор.

## Обоснование каждой коллекции

| Коллекция               | Почему такой выбор                                                        |
|-------------------------|--------------------------------------------------------------------------|
| `Map<Tag, Set<CourseId>>` | ключ — тег, основная операция «взять множество по тегу» O(1); `HashMap`    |
| `Set<CourseId>`           | id внутри тега должен быть уникальным; `LinkedHashSet` заодно хранит порядок добавления |
| пересечение             | идем от уже найденного множества и делаем `retainAll` — чем раньше нашли маленькое, тем дешевле |

Прямая структура `Map<Course, Set<Tag>>` решила бы обратную задачу
(«теги курса») за O(1), но «курсы по тегу» потребовали бы перебора —
потому и нужен инвертированный индекс.

## Инварианты

- **Пустые set не остаются**: после `remove`, когда из тега уходит последний
  id, запись удаляется из индекса целиком — иначе индекс копит мусорные
  ключи, а тесты на `tagCount` стали бы лживыми.
- **Пересечение нескольких тегов** — курс попадает в результат только если у
  него есть все теги; отсутствующий тег → пустое множество (не исключение).
- **Удаление курса** — id вычищается из всех его тегов одной операцией.

## Сложности

| Операция        | Сложность            |
|-----------------|----------------------|
| `add` курса     | O(t), t — число тегов курса, каждый O(1) |
| `remove` курса  | O(t)                 |
| пересечение k тегов | O(k · |m|), |m| — размер наименьшего множества |
| `coursesWithAny`| O(сумма размеров множеств) |
