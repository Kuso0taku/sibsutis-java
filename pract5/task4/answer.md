# Задание 4. Очередь ожидания

`Waitlist` построен на `ArrayDeque` (строгий FIFO, O(1) на обоих концах).
Реализация очереди наружу не отдается — только методы-операции.

## Пары методов

| Операция            | Мягкий вариант | Строгий вариант | Поведение при пустой очереди        |
|---------------------|----------------|-----------------|-------------------------------------|
| добавить в конец    | `offer`        | `add`           | `offer` → `false`, `add` → `IllegalStateException` |
| посмотреть первого  | `peek`         | `element`       | `peek` → `null`, `element` → `NoSuchElementException` |
| извлечь первого     | `poll`         | `remove`        | `poll` → `null`, `remove` → `NoSuchElementException` |

- `add`/`remove`/`element` — «старый» стиль `Collection`: ошибка через исключение.
- `offer`/`poll`/`peek` — «очередевый» стиль `Queue`: сигнал через
  `false`/`null`, что удобно для ограниченных очередей и производителей.
- `Queue` расширяет `Collection`, поэтому в интерфейсе есть оба набора.

В коде пустая очередь — ожидаемый сценарий, поэтому основной путь возвращает
`Optional` (`next`, `take`), а исключающие версии (`nextOrThrow`, `takeOrThrow`)
оставлены для тех мест, где пустая очередь действительно ошибка.
