# Задание 2. Set и уникальность

## Выбор реализации

| Реализация       | Порядок            | Сложность add/contains | Когда брать                         |
|------------------|--------------------|------------------------|-------------------------------------|
| `HashSet`        | не гарантирован    | O(1) в среднем         | порядок не важен                    |
| `LinkedHashSet`  | порядок вставки    | O(1) в среднем         | **наш случай**: дубликаты + порядок |
| `TreeSet`        | отсортированный    | O(log n)               | нужен порядок по значению           |

Требование «удалить дубликаты, сохранив первый порядок появления» выполняет
только `LinkedHashSet`. `HashSet` даст уникальность, но порядок результата
не определен; перебор вариантов на `ArrayList.contains` работает, но это
O(n²) на ровном месте.

## Влияние equals/hashCode

Set определяет дубликат так:

1. вычисляет `hashCode` и ищет корзину;
2. в найденной корзине сравнивает элементы через `equals`.

Отсюда два следствия:

- нет `equals`/`hashCode` — сравнение идет по ссылке, и три разных объекта
  с одинаковым значением останутся в set (см. `PlainCode` в тесте);
- `hashCode` не согласован с `equals` — равные объекты попадают в разные
  корзины, set перестает находить дубликаты.

В `CourseCode` оба метода построены на нормализованном значении, поэтому
`"java-101"`, `" JAVA_101 "` и `"Java 101"` — один и тот же элемент.
