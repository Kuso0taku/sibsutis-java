# Задание 11. Выбор по нагрузке

| # | Сценарий                   | Интерфейс / реализация            | Главные операции                          | Цена памяти / порядка                                   |
|---|----------------------------|-----------------------------------|-------------------------------------------|---------------------------------------------------------|
| 1 | каталог по ID              | `Map` → `HashMap`                 | `get`/`put` O(1) среднее                  | O(n), порядок не гарантирован                           |
| 2 | отсортированный leaderboard| `NavigableMap` → `TreeMap`        | `put` O(log n), `firstKey` O(log n)       | O(n), узлы дерева дороже массива                        |
| 3 | очередь                    | `Queue` → `ArrayDeque`            | `offer`/`poll`/`peek` O(1)                | O(n) массив, без накладных узлов                        |
| 4 | уникальные теги с порядком | `Set` → `LinkedHashSet`           | `add`/`contains` O(1) среднее             | O(n) + связи порядка, порядок вставки                   |
| 5 | диапазонный поиск          | `NavigableMap` → `TreeMap`        | `subMap`/`headMap` O(log n + k)           | O(n), ключи должны быть `Comparable`                    |
| 6 | частый доступ по индексу   | `List` → `ArrayList`              | `get(i)` O(1), `add` в конец амортиз. O(1)| O(n) непрерывный массив, вставка в середину O(n)        |

## Обоснование

- **1** — ключ `CourseId`, основная операция «найти по id»: хеш дает O(1),
  а порядок в каталоге не нужен.
- **2** — нужен порядок по счету и быстрый «топ»: `TreeMap` держит ключи
  отсортированными, `firstKey`/`pollFirstEntry` дают лучший результат.
- **3** — строгий FIFO: `ArrayDeque` быстрее `LinkedList` (нет узлов).
- **4** — уникальность + порядок появления: `LinkedHashSet` совмещает оба
  требования; `HashSet` порядок потеряет, `TreeSet` отсортирует, а не сохранит.
- **5** — интервалы: только упорядоченная структура может `subMap` за
  O(log n + k); хеш-таблица вынуждает полный перебор.
- **6** — частая выборка по индексу: `ArrayList.get(i)` — O(1) и хорошая
  локальность; `LinkedList.get(i)` — O(n).

Конкретные реализации сценариев 2 и 5 — в `Leaderboard` и `RangeIndex`.
