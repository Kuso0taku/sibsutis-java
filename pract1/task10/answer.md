# Конфликт default-методов

## Ошибка компиляции

```java
interface Notifier { default String name() { return "notifier"; } }
interface Logger   { default String name() { return "logger"; } }

class NotifierLogger implements Notifier, Logger {}
// error: name() is inherited from unrelated types
```

Компилятор не может выбрать одну из двух реализаций: у интерфейсов нет
иерархии, значит «более специфичного» default-метода не существует.

## Разрешение

```java
class NotifierLogger implements Notifier, Logger {
  @Override
  public String name() { return "notifier+logger"; }
}
```

Явный override в классе — единственный способ разрешить конфликт.
Абстрактный класс в этом случае выигрывает только тем, что может переопределить
метод у себя, но тогда второй интерфейс всё равно потребует явного выбора.

## Почему множественное наследование поведения требует явного выбора

Java позволяет наследовать поведение от многих интерфейсов, потому что у
интерфейсов нет состояния. Но «наследовать два одинаковых метода» — это
неопределённость, а не магия разрешимости: компилятор не знает, какое
поведение имел в виду автор класса. Поэтому молчаливого выбора нет —
и это защищает от скрытого изменения поведения при добавлении интерфейса.
