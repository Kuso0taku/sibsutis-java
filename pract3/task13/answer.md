# Удаление type code

## Было

`announce(String notificationType, ...)` со `switch`: каждое новое значение —
правка метода, забытый `default` превращается в исключение в рантайме.

## Стало

`NotificationChannel` + реализации `EmailChannel`, `SmsChannel`, `PushChannel`.
`Notifier` зависит от интерфейса, полиморфизм выбирает поведение.
Новый канал — новый класс, `Notifier` не меняется.

## Граница оправданного полиморфизма

Класс на каждую строку конфигурации — перебор, если поведение отличается
только данными. Пример оправданного type code: формат вывода числа
(`"rub"/"usd"`) — там ведёт себя один и тот же код, меняется только константа.
Полиморфизм оправдан, когда **меняется логика**, а не значение:
switch разрастается, требует `default`, и новый вариант забывают обработать.
Тогда различия поведения должны жить в подклассах, а не в строках.
